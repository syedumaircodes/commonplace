## Version control

The next step was to setup git and github, I already have both installed and setup so I just skimmed through the section and moved on. I really liked how the curriculum makes new comers understand how the git workflow and branches work.

A change moves through four places. It starts in the working directory, is staged, committed to the local repository, and only leaves the machine when pushed. Fetch and pull bring the remote's history back the other way.

<GitFlow caption="commits travel outward, fetch and pull travel back" />

Branches make experiments cheap: work happens on a copy of the history, and it only joins the main line when it is worth keeping.
