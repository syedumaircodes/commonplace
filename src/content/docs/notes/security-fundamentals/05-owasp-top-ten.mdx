Nobody secures software alone. A small number of organizations publish the lists, names, and guidance that the rest of the industry relies on, and much of this material is freely available. Four names come up repeatedly, each with a different role but a shared goal of describing security problems in a common way.

- OWASP, the Open Worldwide Application Security Project, is a non-profit foundation dedicated to improving software security. Its projects are open and built by volunteers.

- MITRE is the organization behind the catalogs that security professionals use every day, operated for the public good.

- NIST, the National Institute of Standards and Technology, is a U.S. agency that writes standards, including the definitions and frameworks used in security.

- CISA, the Cybersecurity and Infrastructure Security Agency, is the U.S. agency that tracks the problems attackers are actively using right now.

Together, these four organizations have different jobs but one goal, making sure everyone describes the same problems the same way.

The OWASP Top 10 is a ranked list of the ten most critical security risks facing web applications. OWASP updates it every few years as the data changes, and it is not just someone's opinion. It is built from what people actually find when they test real applications.

- Mistakes in code or bugs due to wrong or incomplete logic.
- Broken access control.
- Compromised libraries and dependencies.

All of the above are categories that OWASP uses to categorize security vulnerabilities. On the OWASP website, the project page describes the list as the reference standard for the most critical web application security risks. The list changes over time because the mistakes people make change as well. It is presented as an awareness document, a broad consensus about what goes wrong most often.
